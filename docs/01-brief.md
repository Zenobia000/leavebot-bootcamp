# 01 Brief — LeaveBot

> 目的：讓員工送出請假後能確認申請已登記，並可再次查閱。

文件狀態：已確認；負責人／審查者：LeaveBot 小組；效率基準：未量測。

## 問題與證據

好日子科技目前用訊息收假單。員工送出後不知道是否登記成功，也無法自行核對紀錄。此問題來自本次題目；尚無處理時間或錯單率的量測資料。

## 目標與成功判準

### G-01｜讓員工核對請假是否登記成功

有效假單送出後應顯示待審核紀錄；重新整理或切換選定員工後，列表仍只顯示該員工的紀錄。依 PRD 操作成功與失敗流程，核對資料庫筆數、狀態與員工隔離。目前沒有流程效率基準，本版以可重做的操作和測試作為交付判準。

## 範圍與非目標

本次只交付員工填表與核對待審核紀錄。以下功能留給後續決策：

| ID | 這次不做 | 理由與重看時機 |
|---|---|---|
| NG-01 | 登入、主管核准與駁回 | 先完成員工送出流程；正式開放使用前須處理身分與授權 |
| NG-02 | 特休額度、同組人數與國定假日 | 需先取得適用規章與資料，再決定計算方式 |
| NG-03 | 一句話 AI 解析、附件與部署 | 不影響本版表單流程的驗收 |

## 限制、假設、風險與決策

範圍依 `course/01-上課/03-LEAVEBOT.md`，技術邊界依 `course/01-上課/04-STACK.md`。本版在本機單服務執行；部署與運作另行規劃。

本版已決定：理由選填、最多 200 個 Unicode 字元；接受過去日期；再次獨立送出可新增一筆紀錄，請求處理期間停用按鈕。半天只接受單一工作日。這些規則由 PRD、SRS 與測試承接。

- 前提：以選單選員工即可完成目前流程；這不提供操作人身分驗證。
- 存取風險：任何操作人都可切換所選員工並查看對應資料。正式開放使用前須設計身分與授權。
- 規章風險：目前只計週一至週五，不含國定假日；導入其他規章前須重新確認工作日計算。

目前沒有阻塞主流程的待決事項；若改動上述規則，先更新 PRD 與驗收條件。
