# 03 SRS — LeaveBot（講師參考）

> 上游：`docs/02-prd.md`。每條 FR 承接可觀察的驗收條件；不新增主管、額度或 AI 功能。

## 功能需求

| 編號 | 系統必須做到的行為 | 來源 |
|---|---|---|
| FR-01 | 有效請假單由後端計算天數、存為 `pending`，並回傳可在所選員工列表查看的紀錄 | AC-01.1 |
| FR-02 | 必填缺漏、未知員工、非法假別／時段、無效或反向日期一律拒絕；拒絕時不新增假單 | AC-01.2 |
| FR-03 | 起迄日皆納入計算，僅週一至週五算工作日；單日工作日的上午／下午為 0.5 天；跨日半天、週末半天與零工作日拒絕 | AC-01.3 |
| FR-04 | 理由選填，最多 100 個 Unicode 字元；超過時拒絕且不新增假單 | AC-01.4 |
| FR-05 | 不接受客戶端指定的 `status` 或 `days`；狀態與天數由後端決定 | AC-01.5 |
| FR-06 | 提供員工選單，依所選員工列出已存假單；重新整理或重開後資料仍在，其他員工的假單不混入 | AC-02.1 |

## 品質與失敗行為

| 編號 | 可驗證的要求 | 如何驗證 |
|---|---|---|
| NFR-01 | 理由以純文字呈現，不將使用者輸入當 HTML 或指令執行 | 輸入含 HTML 標記的理由，操作畫面核對呈現方式 |
| NFR-02 | 自動化測試使用隔離資料庫，不讀寫開發資料庫 | 檢查測試設定與暫存資料庫接縫 |

## 決策與流程圖

講師在本快照選定：接受過去日期；重複送出可新增另一筆，送出期間停用按鈕；理由選填。卡 J 已將理由上限從 200 改為 100 字元，FR-04 現行值是 100。這些是課堂決策，不是從真實公司訪談推得。

卡 D 的流程圖已放在 `diagrams/submit-leave.html`，涵蓋成功、拒絕且不存檔、查看所選員工紀錄。
