# 03 SRS — LeaveBot

> 誰寫的：系統分析。給實作和測試看。讀完要能自己算出「這一筆會得到幾天、畫面上是哪一句、會不會進資料庫」。
> 上游：`docs/02-prd.md`。這裡不重寫員工的故事，也不新增主管、額度或 AI。

文件狀態：已確認；日期：2026-10-27；負責人／審查者：LeaveBot 小組。

## 功能需求

主流程是：先檢查輸入，再算工作日，通過才存檔，然後只把這位員工的假單列出來。

| ID | 系統行為 | 來源 AC |
|---|---|---|
| FR-01 | 合法的整天申請算出天數、存成待審核，並出現在這位員工的列表 | AC-01.1 |
| FR-02 | 缺必填、員工不在名單、假別或時段不對、日期不對：拒絕且不新增，說明見下表 | AC-01.2 |
| FR-03 | 只計週一到週五；合法半天是 0.5 天；非法半天與零工作日拒絕 | AC-01.3 |
| FR-04 | 理由可以空白。200 個字可以登記，201 個字拒絕且不新增 | AC-01.4 |
| FR-05 | 請求裡若帶了狀態或天數，整筆拒絕，不採用那兩個值，不新增 | AC-01.5 |
| FR-06 | 依目前選到的員工列出已存檔的假單，不混入別人的 | AC-02.1 |

## 規則與資料字典

天數和狀態由系統決定，送出端不能指定。新假單的狀態是待審核，系統內記為 `pending`。

- 員工（FR-02、FR-06）：名單只有小安（id 1）、小晴（id 2）。其他識別值拒絕，不新增。
- 假別（FR-02）：只接受 `annual`（特休）、`personal`（事假）、`sick`（病假）。
- 時段（FR-02、FR-03）：`full` 整天、`am` 上午、`pm` 下午。上午和下午只在開始日等於結束日，而且那天是工作日時成立。
- 日期（FR-01、FR-02、FR-03）：`YYYY-MM-DD`，起迄兩天都算進去。過去的日期可以。格式不對，或結束早於開始，就拒絕。
- 天數（FR-03）：週一到週五各算 1。同一個工作日的上午或下午算 0.5。算出 0 天就拒絕。不含國定假日。
- 理由（FR-04）：可以空白。以一個 Unicode code point 為一個字，計法和 Python 的 `len` 相同。200 個字可以，201 個字拒絕。
- 狀態與天數（FR-01、FR-05）：伺服器產生。請求裡出現 `status` 或 `days`，整筆拒絕。

必填是員工、假別、開始日期、結束日期、時段。

2026-10-20 是週二，10-23 是週五，10-26 是週一，10-24 與 10-25 是週末。週五到下週一只算週五和週一，是 2 天。

## 品質需求

- NFR-01｜理由當純文字：畫面上看到的是員工打的字。理由裡若有 HTML 標籤，那些字要照原樣出現，不能變成網頁效果。驗證方式是拿含標籤的理由走一次畫面。還沒有人做過這次操作，就不能標通過。
- NFR-02｜測試用自己的資料庫：自動測試使用暫時資料庫，不讀、不寫開發時那份。檢查測試怎麼取得資料庫路徑。

沒有依據的效能數字不寫。這版沒有量過回應時間。
