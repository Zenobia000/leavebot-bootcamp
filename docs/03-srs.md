# 03 SRS — LeaveBot（講師參考）

> 上游：`docs/02-prd.md`。每條 FR 承接可觀察的驗收條件；不新增主管、額度或 AI 功能。

文件狀態：講師參考已確認；負責人／審查者：課程講師。

## 功能需求

核心行為是「驗證 → 計算 → 保存 → 讓所選員工核對」。以下編號供設計與測試引用：

- **FR-01（AC-01.1）：**有效假單由後端計算天數、存為 `pending`，回傳可在所選員工列表查看的紀錄。
- **FR-02（AC-01.2）：**必填缺漏、未知員工、非法假別／時段、無效或反向日期均拒絕；拒絕時不新增假單。
- **FR-03（AC-01.3）：**起迄日皆納入計算，只計週一至週五；單日工作日的上午／下午為 0.5 天。跨日半天、週末半天與零工作日均拒絕。
- **FR-04（AC-01.4）：**理由選填，最多 200 個 Unicode 字元；超過時拒絕且不新增假單。
- **FR-05（AC-01.5）：**不接受客戶端指定的 `status` 或 `days`；兩者由後端決定。
- **FR-06（AC-02.1）：**提供員工選單，依所選員工列出已存假單；重新整理或重開後資料仍在，不混入其他員工紀錄。

## 品質與失敗行為

- **NFR-01｜安全呈現：**理由以純文字呈現，不把輸入當 HTML 或指令執行。以含 HTML 標記的理由操作畫面驗證。
- **NFR-02｜測試隔離：**自動化測試使用暫存資料庫，不讀寫開發資料庫；檢查測試接縫及資料庫路徑。

## 決策與流程圖

講師在本快照選定：接受過去日期；重複送出可新增另一筆，送出期間停用按鈕；理由選填且上限 200 字元。這些是課堂決策，不是從真實公司訪談推得。

卡 D 的流程圖已放在 `diagrams/submit-leave.html`，涵蓋成功、拒絕且不存檔、查看所選員工紀錄。

## 規則與邊界例子

- **員工（FR-02、FR-06）：**只接受提供的員工識別值；未知值拒絕且不新增資料。
- **假別（FR-02）：**只接受 `annual`、`personal`、`sick`。
- **日期（FR-02、FR-03）：**使用 ISO `YYYY-MM-DD`，計算包含起迄日；接受過去日期。格式無效或結束早於開始都拒絕。
- **時段與天數（FR-03）：**整天每個週一至週五為 1，單日工作日上午／下午為 0.5；跨日半天、週末半天、零工作日均拒絕。例如週五到週一整天為 2；週六到週日為 0，須拒絕。
- **理由（FR-04）：**選填，200 個 Unicode 字元可接受，201 個拒絕。
- **狀態／天數（FR-01、FR-05）：**由後端產生，初始狀態為 `pending`；客戶端傳入這兩欄即拒絕。

API 的確切欄位名稱、錯誤格式與排序由 SDS 定；此處定義行為，不假定未審核的介面契約。NFR-01 的人工驗證若未執行不得標通過。
