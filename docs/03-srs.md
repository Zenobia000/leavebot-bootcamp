# 03 SRS — LeaveBot

> 上游：`docs/02-prd.md`。每條 FR 承接可觀察的驗收條件；不新增主管、額度或 AI 功能。

文件狀態：已確認；負責人／審查者：LeaveBot 小組。

## 功能需求

核心行為是「驗證 → 計算 → 保存 → 讓所選員工核對」。FR 編號及其來源供設計與測試查找；計算邊界在下段展開。

| ID | 可觀察的系統行為 | 來源 AC |
|---|---|---|
| FR-01 | 有效假單由後端計算天數、存為 `pending`，並回傳可在所選員工列表查看的紀錄 | AC-01.1 |
| FR-02 | 必填缺漏、未知員工、非法假別／時段、無效或反向日期均拒絕，且不新增假單 | AC-01.2 |
| FR-03 | 起迄日納入計算、只計週一至週五；非法半天與零工作日拒絕 | AC-01.3 |
| FR-04 | 理由選填、最多 200 個 Unicode 字元；超過時拒絕且不新增假單 | AC-01.4 |
| FR-05 | `status` 與 `days` 由後端決定；客戶端指定時拒絕 | AC-01.5 |
| FR-06 | 提供員工選單，列出所選員工的持久紀錄，不混入其他員工資料 | AC-02.1 |

## 規則與資料字典

- 員工（FR-02、FR-06）：只接受提供的員工識別值；未知值拒絕且不新增資料。
- 假別（FR-02）：只接受 `annual`、`personal`、`sick`。
- 日期（FR-02、FR-03）：使用 ISO `YYYY-MM-DD`，計算包含起迄日；接受過去日期。格式無效或結束早於開始都拒絕。
- 時段與天數（FR-03）：整天每個週一至週五為 1，單日工作日上午／下午為 0.5；跨日半天、週末半天、零工作日均拒絕。例如週五到週一整天為 2；週六到週日為 0，須拒絕。
- 理由（FR-04）：選填，200 個 Unicode 字元可接受，201 個拒絕。
- 狀態／天數（FR-01、FR-05）：由後端產生，初始狀態為 `pending`；客戶端傳入這兩欄即拒絕。

## 品質需求

- NFR-01｜安全呈現：理由以純文字呈現，不把輸入當 HTML 或指令執行。以含 HTML 標記的理由操作畫面驗證。
- NFR-02｜測試隔離：自動化測試使用暫存資料庫，不讀寫開發資料庫；檢查測試接縫及資料庫路徑。
