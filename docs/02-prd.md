# 02 PRD — LeaveBot

> 上游：`docs/01-brief.md`。本文件定義員工可見的結果與驗收條件。

文件狀態：已確認；負責人／審查者：LeaveBot 小組。

## 使用者、工作與情境

主要使用者是好日子科技的員工。員工在同一頁選擇自己的名字，填入假別、日期、時段與選填理由，送出後看到回饋與自己的假單列表；重新整理後仍可查看。沒有登入，員工由下拉選單選取。

主流程：選員工 → 填表 → 送出 → 後端驗證與計算工作日 → 存為 `pending` → 更新所選員工列表。輸入被拒絕時顯示錯誤，資料庫不新增假單。

## 故事與驗收條件

### US-01 送出請假單（G-01）

身為員工，我想填表送出請假，並知道系統是否已登記，以免只留下無法核對的訊息。

- AC-01.1：Given 選定有效員工、合法假別與工作日 When 送出完整表單 Then 新增一張 `pending` 假單，顯示由程式計算的天數，並在自己的列表看到它。
- AC-01.2：Given 缺少必填欄位、員工不存在、假別或時段非法、日期格式錯誤，或結束日期早於開始日期 When 送出 Then 顯示錯誤且不新增假單。
- AC-01.3：Given 起迄涵蓋週末 When 送出整天假 Then 只計週一至週五；單一工作日的上午／下午各為 0.5 天；跨日半天、週末半天及零工作日申請要拒絕且不新增假單。
- AC-01.4：Given 理由留空或不超過 200 個 Unicode 字元 When 送出其他欄位合法的表單 Then 可登記；理由超過 200 字元要拒絕且不新增假單。
- AC-01.5：Given 客戶端自行帶入 `status` 或 `days` When 送出 Then 拒絕且不新增假單；狀態與天數只由後端決定。

### US-02 核對自己的假單（G-01）

身為員工，我想重新整理或切換選定員工後查看對應假單，確認登記結果不會消失或混入他人紀錄。

- AC-02.1：Given 已有不同員工的假單 When 重新整理或切換所選員工 Then 只顯示目前所選員工的持久紀錄，不混入其他員工資料。

## 產品規則與體驗

成功送出後，使用者會看到 `pending` 紀錄；重新整理仍可核對。輸入被拒絕時應看到可理解的錯誤，並可修正表單；資料庫沒有新假單。

| 情境／規則 | 使用者看見的結果與資料變化 | 來源／AC |
|---|---|---|
| 成功送出 | 顯示待審核紀錄；重新整理仍可查看 | 題目、AC-01.1、AC-02.1 |
| 輸入被拒絕 | 顯示錯誤、可修正表單；不新增假單 | 題目、AC-01.2 至 AC-01.5 |
| 送出期間連點 | 按鈕暫時停用，請求結束後恢復 | 本版決策；尚無獨立 AC／TC |
| 再次獨立送出 | 不自動去重，新增另一筆紀錄 | 本版決策；尚無獨立 AC／TC |
| 切換員工 | 只顯示當前所選員工的列表 | 題目、AC-02.1 |

理由以純文字保存與呈現；接受過去日期。送出期間連點與再次獨立送出尚無獨立 TC，需在測試計畫列為覆蓋缺口。

## 範圍、依賴與待決

非目標沿用 Brief 的 NG-01 至 NG-03。依賴員工名單與本機服務；沒有身分驗證，所以「自己的假單」只指目前選定員工的列表。取消流程、排序與空列表文案尚未成為成功判準。本版沒有阻塞主流程的待決事項；改動規則時先同步修訂規格與驗收。
