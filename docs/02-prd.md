# 02 PRD — LeaveBot（講師參考）

> 上游：`docs/01-brief.md`。這是教學用已確認決策，不宣稱曾訪談真實員工。

## 使用者與流程

主要使用者是虛構公司的員工。員工在同一頁選擇自己的名字，填入假別、日期、時段與選填理由，送出後看到回饋與自己的假單列表；重新整理後仍可查看。沒有登入，員工由下拉選單選取。

主流程：選員工 → 填表 → 送出 → 後端驗證與計算工作日 → 存為 `pending` → 更新所選員工列表。輸入被拒絕時顯示錯誤，資料庫不新增假單。

## 故事與驗收

### US-01 送出請假單（G-01）

身為員工，我想填表送出請假，並知道系統是否已登記，以免只留下無法核對的訊息。

- **AC-01.1** Given 選定有效員工、合法假別與工作日 When 送出完整表單 Then 新增一張 `pending` 假單，顯示由程式計算的天數，並在自己的列表看到它。
- **AC-01.2** Given 缺少必填欄位、員工不存在、假別或時段非法、日期格式錯誤，或結束日期早於開始日期 When 送出 Then 顯示錯誤且不新增假單。
- **AC-01.3** Given 起迄涵蓋週末 When 送出整天假 Then 只計週一至週五；單一工作日的上午／下午各為 0.5 天；跨日半天、週末半天及零工作日申請要拒絕且不新增假單。
- **AC-01.4** Given 理由留空或不超過 100 個 Unicode 字元 When 送出其他欄位合法的表單 Then 可登記；理由超過 100 字元要拒絕且不新增假單。
- **AC-01.5** Given 客戶端自行帶入 `status` 或 `days` When 送出 Then 拒絕且不新增假單；狀態與天數只由後端決定。

### US-02 核對自己的假單（G-01）

身為員工，我想重新整理或切換選定員工後查看對應假單，確認登記結果不會消失或混入他人紀錄。

- **AC-02.1** Given 已有不同員工的假單 When 重新整理或切換所選員工 Then 只顯示目前所選員工的持久紀錄，不混入其他員工資料。

## 範圍與待決

非目標沿用 Brief 的 NG-01 至 NG-03。理由作為純文字保存與呈現，不執行其中內容。卡 J 的需求變更將理由上限從 200 改為 100，沿用 AC-01.4，見 `issues/002-reason-limit.md`。接受過去日期；不自動去重，送出期間停用按鈕以避免連點。這一組講師參考決策沒有阻塞主線的待決項；小組採用不同決策時須先同步修訂規格與驗收。
