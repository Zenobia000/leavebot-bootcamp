# 02 PRD — LeaveBot

> 誰寫的：產品。給設計和測試看，講員工會看到什麼、怎樣算過。
> 上游：`docs/01-brief.md`。每一種輸入的天數、說明與筆數，以 `docs/03-srs.md` 的表為準。

文件狀態：已確認；日期：2026-10-27；負責人／審查者：LeaveBot 小組。

驗收編號沿用後續快照的測試已經對上的編號。同一條驗收若有好幾種輸入，每種輸入在 SRS 各占一列，一列只有一個結果。

## 使用者、工作與情境

用的人是好日子科技的員工。同一個頁面上，先從下拉選單選自己的名字。名單是小安、小晴。再填假別、開始日期、結束日期、時段。理由可以空白。沒有登入。

送出之後有兩種結果。成功的話，列表出現一筆待審核，上面有系統算出的天數；重新整理還在。失敗的話，畫面上是一句說明，已經填的內容還在，可以改完再送，列表不會多一筆。

## 故事與驗收條件

### US-01 送出請假單（G-01）

身為員工，我要送出請假，並知道有沒有登記成功，以免訊息送出之後無從核對。

- AC-01.1：Given 選了小安、特休、2026-10-20 到 2026-10-20、整天、理由空白 When 送出 Then 小安的列表多一筆待審核，天數是 1，重新整理後還在。
- AC-01.2：Given 缺了必填、員工不在名單、假別或時段不在允許值、日期格式不對，或結束早於開始 When 送出 Then 不新增假單，畫面顯示 SRS 表上該列的說明。
- AC-01.3：Given 要計算工作日或半天 When 送出 Then 結果與 SRS 表上標了 AC-01.3 的那一列相同。成功的列會新增待審核；拒絕的列不新增。
- AC-01.4：Given 其餘欄位合法 When 送出 100 字、101 字或 201 字的理由 Then 結果與 SRS 表上對應的那一列相同。100 字會登記，101 字和 201 字都不新增。
- AC-01.5：Given 送出的資料裡自己帶了狀態或天數 When 送出 Then 整筆拒絕，不採用那兩個值，不新增假單。狀態和天數只由系統決定。

### US-02 核對自己的假單（G-01）

身為員工，我要在重新整理或換成另一位員工之後，看到對的那一份列表。

- AC-02.1：Given 小安已經有一筆假單、小晴沒有 When 重新整理或改選其中一人 Then 只顯示目前選到的這位。選小晴時列表是空的。

必填是員工、假別、開始日期、結束日期、時段。

## 產品規則與體驗

成功時，員工看到待審核和天數，重新整理還在。失敗時，看到該列的說明，改完可以再送，列表筆數不變。

| 情境／規則 | 員工看見的結果與資料變化 | 來源／AC |
|---|---|---|
| 成功送出 | 多一筆待審核，重新整理還在 | AC-01.1、AC-01.3、AC-01.4 |
| 輸入被拒絕 | 看到該列說明，表單還在，不新增 | AC-01.2、AC-01.3、AC-01.5、AC-01.4 |
| 送出期間連點 | 請求結束前按鈕停用，結束後恢復 | 本版決策；尚無獨立驗收 |
| 再次獨立送出 | 再多一筆，兩筆都留下 | 本版決策；尚無獨立驗收 |
| 切換員工 | 只顯示目前選到的這位 | AC-02.1 |

理由以純文字呈現。空列表要寫什麼、列表怎麼排、做一半想取消，都還沒定，不算這版的成功標準。

## 範圍、依賴與待決

非目標沿用 Brief 的 NG-01 至 NG-03。這版依賴員工名單（小安、小晴）和本機上的服務。
